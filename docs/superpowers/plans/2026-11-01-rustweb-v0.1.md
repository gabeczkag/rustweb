# RustWeb v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Zbudować `rustweb` — framework webowy dla Rusta w duchu FastAPI, oparty na axum, z walidacją, błędami 422, automatycznym OpenAPI i benchmarkiem niskiego opóźnienia.

**Architecture:** Cienka warstwa nad axum/tower/hyper. Makra proceduralne zamieniają funkcje handlerów w unit structy rejestrujące trasę i metadane OpenAPI. `RustWeb` zbiera trasy i buduje dokument OpenAPI raz przy starcie. `ApiJson`/`ApiQuery`/`ApiPath` walidują wejście i zwracają błędy w kształcie FastAPI.

**Tech Stack:** Rust 1.99, axum 0.8.9, tokio 1.54, utoipa 6.0, utoipa-swagger-ui 10.0, validator 0.21, serde 1, syn 2, quote 1.

**Spec:** `docs/superpowers/specs/2026-11-01-rustweb-design.md`

## Global Constraints

- Rust edition 2021, MSRV zgodny z zależnościami (utoipa wymaga 1.88; mamy 1.99).
- axum przypięty do `0.8.9`; utoipa `6.0`; utoipa-swagger-ui `10.0`; validator `0.21`.
- Makra w osobnym crate `rustweb-macros`, re-eksportowane przez `rustweb`.
- Ścieżki w kodzie generowanym przez makra: `::rustweb::...` (wymaga `extern crate self as rustweb;` w lib).
- Zero dodatkowych layerów w hot path; OpenAPI budowane wyłącznie przy starcie.
- Wszystkie błędy HTTP zwracają JSON `{"detail": ...}`.
- Każdy task kończy się zielonym testem i commitem.

## Review Focus

- Zły JSON albo brak `Content-Type: application/json` → 422 z `detail[]`, nie 400/415 z axum.
- Błąd walidacji zagnieżdżonego pola/listy → `loc` zawiera pełną ścieżkę, brak paniki.
- Ta sama ścieżka z GET i POST → obie metody działają i obie są w OpenAPI.
- `ApiResult<()>` ze `status = 204` → pusty body i poprawny status.
- `ApiPath<u64>` na `/users/abc` → 422, nie 400.
- Odpowiedź JSON ma `Content-Type: application/json`.

```rust
#[allow(non_camel_case_types)]
#[derive(Clone, Copy)]
pub struct hello;

impl hello {
    async fn __rustweb_body() -> &'static str { "Hello, RustWeb!" }
    async fn __rustweb_handler() -> axum::response::Response { /* IntoResponse */ }
}

impl ::rustweb::Route for hello {
    fn method(&self) -> ::rustweb::axum::http::Method { ::rustweb::axum::http::Method::GET }
    fn path(&self) -> &'static str { "/hello" }
    fn operation(&self) -> ::rustweb::openapi::path::Operation { Default::default() }
    fn schemas(&self) -> Vec<(String, ::rustweb::openapi::RefOr<::rustweb::openapi::schema::Schema>)> { Vec::new() }
    fn register(self, router: ::rustweb::axum::Router) -> ::rustweb::axum::Router {
        router.route("/hello", ::rustweb::axum::routing::get(hello::__rustweb_handler))
    }
}
```

- [ ] **Step 3: Implement error, extractor and model macro**

`error.rs`: `ApiError { status: StatusCode, detail: Value }`; `IntoResponse` serializuje `json!({"detail": self.detail})`. `From<ValidationErrors>` flattenuje `ValidationErrorsKind::{Field, Struct, List}` rekurencyjnie do `Vec<Value>` z `loc: ["body", pole, ...]`, `msg` z `message` lub `code`, `type` = `code`, `ctx` = `params`. `From<JsonRejection>` → 422 `{type: "json_invalid", loc: ["body"], msg: rejection.body_text()}`.

Dodaj też `#[derive(utoipa::ToSchema)] pub struct ApiErrorBody { pub detail: Value }` — schemat dokumentacji błędów (nazwa `ApiErrorBody`). `ApiError` może trzymać `detail: Value` bez derive'u.

`extract.rs`: `ApiJson<T>` z `Deref<Target = T>`, `FromRequest<S>` gdzie `T: DeserializeOwned + Validate`, `S: Send + Sync`. Po deserializacji `value.validate()`; błąd → `ApiError::unprocessable`.

Makro `#[model]`: dodaje brakujące `#[derive(::serde::Serialize, ::serde::Deserialize, ::utoipa::ToSchema, ::validator::Validate)]`; jeśli użytkownik już ma któryś derive, nie duplikuj. Struktura i atrybuty pól pozostają bez zmian.

- [ ] **Step 3: Implement metadata parsing and codegen**

W `rustweb-macros` dodaj parser atrybutów trasy (`RouteArgs`) i parser sygnatury:

- Każdy `Path<T>` z patternem `Ident` → parametr path o nazwie ident, schemat `<T as PartialSchema>::schema()`.
- `Path<(A, B)>` z patternem tuple → parametry w kolejności segmentów `{...}`.
- `ApiQuery<T>`/`Query<T>` → `T::into_params(|| Some(ParameterIn::Query))`.
- `ApiJson<T>`/`Json<T>` → request body `application/json` ze schematem `$ref` do `T`.
- Response: wyciągnij `T` z `Json<T>`/`ApiJson<T>` (także z `Result` i tuple); status z atrybutu (domyślnie 200); `204`/brak body → response bez contentu.
- Dodaj response `422` z `$ref` do `ApiErrorBody` tylko gdy jest body/query.
- `schemas()`: `<T as ToSchema>::schemas(&mut v)` + `(T::name(), T::schema())` dla body i response; to samo dla `ApiErrorBody`.

Wygenerowany kod używa builderów `OperationBuilder`, `ParameterBuilder`, `RequestBodyBuilder`, `ResponseBuilder`, `ContentBuilder`, `Ref`.

pub(crate) fn build_openapi(title: &str, version: &str, routes: &[RouteMeta]) -> utoipa::openapi::OpenApi {
    let mut paths = utoipa::openapi::path::PathsBuilder::new();
    let mut schemas = std::collections::BTreeMap::new();
    for meta in routes {
        let method = match meta.method.as_str() {
            "GET" => HttpMethod::Get,
            "POST" => HttpMethod::Post,
            /* PUT, DELETE, PATCH */
            _ => continue,
        };
        paths = paths.path(meta.path, PathItem::new(method, meta.operation.clone()));
        for (name, schema) in &meta.schemas {
            schemas.entry(name.clone()).or_insert_with(|| schema.clone());
        }
    }
    let mut components = utoipa::openapi::schema::ComponentsBuilder::new();
    for (name, schema) in schemas {
        components = components.schema(name, schema);
    }
    utoipa::openapi::OpenApiBuilder::new()
        .openapi(utoipa::openapi::OpenApiVersion::Version32)
        .info(utoipa::openapi::Info::new(title, version))
        .paths(paths.build())
        .components(Some(components.build()))
        .build()
}

async fn create_user(ApiJson(body): ApiJson<CreateUser>) -> ApiResult<Json<User>> {
